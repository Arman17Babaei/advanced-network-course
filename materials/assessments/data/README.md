# Recent paper corpus

This directory contains the machine-readable 2023–2027 literature corpus used to ground the Advanced Networks project idea pool.

## Data model

Collection is deliberately split into two stages:

1. **Freeze each conference venue independently.** Each requested venue is validated for plausible paper counts and required metadata, then stored under `venues/`. Normal corpus assembly reads these frozen files and does not re-query conference endpoints.
2. **Filter IEEE Transactions at paper level.** Journals matching the IEEE/ACM Transactions naming family are scanned, but only networking-systems papers are retained. TON and TNSM are treated as networking journals and their research-paper inventories are retained in full.

This structure makes the corpus reproducible and prevents a broken live endpoint from silently changing the project pool.

## Frozen conference snapshots

`venues/` contains one CSV per requested conference family:

- SIGCOMM
- CoNEXT
- NSDI
- ICNP
- INFOCOM
- SIGMETRICS / POMACS
- IMC
- ACM Multimedia
- NINeS
- MobiCom
- MMSys
- IPDPS
- ICDCS
- OSDI
- USENIX Security

Each row includes title, authors, venue, year, DOI or canonical publication URL where available, keyword labels and their provenance, normalized topic/category labels, and source metadata.

The live adapters and their validation thresholds remain version-controlled under `tools/research/`, but frozen snapshots are the input to normal assembly.

## IEEE Transactions

`transactions/` contains:

- per-journal snapshots used during validation;
- `ieee_transactions_network.csv` — the Transactions-wide networking subset;
- source/coverage audit files generated by the Transactions scan.

For broad journals such as TMC, TVT, TWC, TPDS, TCC, TMM, TDSC, and TNSE, inclusion requires explicit network-systems evidence in the title/keywords: routing, transport, network control/management, network architecture, mobile/edge offloading, RAN, vehicular/satellite networks, etc. Bare wireless/5G/Wi-Fi terminology is not sufficient because it admits sensing and PHY-only work.

## Master generated files

`tools/research/assemble_paper_corpus.py` reads only frozen conference snapshots plus the Transactions-wide filtered file and produces:

- `all_conference_papers.csv` — complete collected conference inventory;
- `ieee_transactions_network.csv` — normalized Transactions networking subset;
- `master_paper_corpus.csv` — all conference papers plus networking-relevant Transactions papers;
- `recent_networking_papers.csv` — network-relevant rows used for project-area mining;
- `PAPER_CORPUS_COVERAGE.csv` — venue/journal/year coverage;
- `PAPER_CORPUS_SUMMARY.md` — generated counts, keyword provenance, and category statistics.

## Keyword provenance

The corpus does **not** pretend inferred keywords are author keywords.

The original `keywords` field is always accompanied by `keyword_provenance`. In assembled outputs:

- `source_index_terms` is populated only when publisher/index metadata is available;
- `derived_keywords` contains OpenAlex model-generated labels or deterministic title/abstract-derived labels;
- `categories` contains the course-specific normalized research taxonomy.

This distinction is important because many conference accepted-paper pages expose title/authors but no author-supplied keyword list.

## Validation

Per-venue validation checks:

- paper count against a conservative or exact known count;
- author coverage;
- DOI or canonical URL coverage;
- keyword coverage after provenance-aware fallback;
- sample records for manual sanity checking.

The corpus is fail-closed: generated master files are not considered valid if a required frozen venue is missing, required metadata is absent, or the Transactions-wide networking subset is implausibly small.

The requested window is 2023–2027. 2027 remains empty for venues/journals whose accepted or published paper metadata is not yet available.
